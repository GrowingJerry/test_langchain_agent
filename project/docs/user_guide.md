# 用户指南

启动后先创建或选择项目，再在“资料与需求”按“资料上传 → 结构与HTML（可选）→ 需求审核”的顺序准备需求。普通文档会直接解析，长文档会进入后台任务；结构化增强直接选择已经入库的 DOCX，不需要重复上传。知识抽取结果须审核后才能作为项目事实使用。

装备资料和场景学习收在“资料与需求”的高级资料中。常规流程在“生成测试用例”直接按已审核需求生成；只有需要装备分配和复杂场景编译时才选择“高级场景生成”。Ollama 不可用时自动使用确定性规则。最后在“用例审查”中完成人工修改、单条对话优化和覆盖检查，再到导出中心生成 Excel、Word 或 Markdown。

所有数据操作都绑定当前 `project_id`，切换项目后请重新确认页面所示项目。
# 需求抽取审核与生成

上传资料支持 `txt`、`md`、`doc`、`docx`、`pdf`。正式的软件需求规格说明书、
用户需求说明书和接口需求文档建议上传 `docx`，以便保留章节和表格结构。`.doc`
文件会尽量自动转换到临时 `docx` 后解析；如果本机没有可用 Word/WPS 自动转换能力，
系统会按文本兜底并提示转换。

需求抽取和审核统一位于“资料与需求 → 3. 需求审核”；生成页面不再重复承担文档抽取职责。
请检查需求编号、标题、正文、结构化字段、推荐测试类型和是否保留。保存审核后的需求清单后，
这些需求才会进入正式需求库。空白模板和模板填写说明不会作为项目事实需求入库。

选择需求后，页面会默认选中系统推荐的测试类型，并展示候选类型、置信度和依据。用户可以修改，
且人工选择优先。测试用例数量仍由用户手动设置；生成前页面会显示需求、推荐类型、最终类型和数量摘要。
