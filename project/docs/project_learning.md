# 项目领域学习

该功能称为“项目学习”，不是训练或微调模型。

## 创建学习任务

进入“文档与知识库 → 场景学习”，填写任务名称、学习目标、领域、仿真对象、目标子系统、主题、预期场景类型、排除主题，并选择文档。第一阶段按目标检索章节和子块形成覆盖候选；第二阶段才对候选调用结构化 Chain，不逐页调用 LLM。

知识类型覆盖术语、子系统、仿真模型、状态变量、输入输出、状态转换、环境因素、故障模式、参数、约束、验证规则和场景模式。每条知识保留适用/不适用条件及来源。

## 几百页书籍

默认 PyMuPDF 逐页解析；可选 Docling 由 `requirements-docs.txt` 管理。技术书籍使用章节感知父子分块，child 保存 `parent_section_id` 和页码范围。扫描页只标记 `needs_ocr=true`。文件哈希避免重复解析，检查点支持中断恢复，单页异常进入报告而不终止全书。

大文件上传后启动 Worker：

```powershell
python scripts/run_learning_worker.py
```

作业可在 UI 查看进度、暂停、恢复和取消。Worker 使用 SQLite 租约，不能并发处理同一 job。

## 审核知识

进入“知识审核”，按状态、类型、来源或冲突筛选。数值参数缺单位时不能批准；书籍参数默认不能成为项目参数；同名符号保留章节作用域。新书不会覆盖当前项目 approved 知识。`rejected` 和 `deprecated` 默认不参与生成。

人工修改场景或用例只形成 feedback candidate。只有人工批准的反馈规则才能参与未来生成；项目规则不自动传播，GLOBAL 必须显式提升，数值参数永远不能自动提升为组织规则。
